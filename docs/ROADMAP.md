## 1. 개발·테스트 중 발견해 고친 문제

| 발견 | 어떻게 찾았나 | 조치 |
|---|---|---|
| 찬스 응원가가 한 번도 나오지 않음 | UI 시즌 자동 플레이에서 배경음악 전환 기록 | 경기 화면 갱신이 공마다 일어나지 않았음 → 공마다 판단 |
| 로딩 안내 글이 로딩 그림·진행 막대와 겹침 | 헤드리스 브라우저 스크린샷 | 타이틀 그림으로 바꾸고 막대 위치 조정 |
| 폰트 파일은 12MB 인데 게임 데이터는 3.6MB | 빌드 크기 측정 | 가져오기 때 이미 압축됨 → 실제 절감은 1.3MB. 첫 로딩의 대부분은 엔진 파일임을 확인 (아래 P1-2) |
| 대졸 지명 선수의 성(두 글자 성) | 코드 검토 | 졸업생 기록에 성·이름을 따로 저장 |

## 2. 새 로드맵

### P1 — 다음 라운드

1. **휴대폰 성능 3단계**
   - 근거: CPU 4배 제한에서 경기 많은 날 2.4초(목표 1.5초), CPU 경기당 45ms 중 경기 준비(선수 변환·오더)가 약 20%.
   - 내용: 팀별 경기용 선수(SimPlayer) 주간 캐시, CPU 감독 판단 단순화, 경기 많은 날은 여러 프레임에 나눠 진행.
   - 검증: `web_bench --throttle=4` 경기 많은 날 1.5초 이하, `test_balance` 분포 동일.
2. **홈 화면에 추가(PWA)**
   - 근거: iPhone Safari 는 전체 화면이 안 되어 가로 화면 사용이 81% 에 그친다. 홈 화면 앱으로 열면 주소창이 없다. 다시 열 때 엔진 10MB 도 캐시에서.
   - 내용: 웹 내보내기의 PWA 설정, 아이콘, 업데이트 시 새 버전 받기 확인.
   - 검증: 헤드리스 브라우저에서 서비스 워커 등록, 오프라인 재실행, 새 버전 배포 후 갱신.
3. **주장·팀 분위기**
   - 근거: 3학년의 존재감이 드래프트 말고는 약하다. 원작(백구의 기적)의 팀 분위기 요소.
   - 내용: 새 시즌에 주장 선출(선택 팝업), 팀 분위기(연승·연패·행사로 변화)가 컨디션에 영향.
   - 검증: 시즌 테스트에서 분위기 변화 폭, 밸런스 테스트 범위 유지.
4. **감독 성장**
   - 근거: 해가 지나도 감독 쪽은 변하는 것이 없다.
   - 내용: 경기·대회 성적으로 감독 경험치 → 특기(작전 성공률 소폭, 스카우트 행동력, 훈련 효과 중 택1).
   - 검증: 5년 시뮬레이션에서 특기별 효과 측정.

### P2

5. **명장면**: 우리 경기의 끝내기·홈런·삼진 장면을 기록해 경기 후 다시 보기
6. **업적·도감**: 특수능력 도감 수집률, 대회 우승·타이틀 업적
7. **선수 이야기**: 슬럼프·재활·라이벌 선수(상대 학교 에이스) 소식
8. **세이브 불러오기 시간** 측정·개선 (4배 제한에서 저장 0.4초)

### P3

9. **효과음 추가** (관중 함성 크기가 점수 차·이닝에 따라)
10. **웹 기반 시스템 텍스트 UI 정리** (Godot 전용 기능 목록 표시)
