## 1. 개발·테스트 중 발견해 고친 문제

| 발견 | 어떻게 찾았나 | 조치 |
|---|---|---|
| 특수능력 85종을 넣자 경기 엔진이 17% 느려짐 (11.7 → 13.6ms/경기) | `bench.gd` 비교 측정 | 상시 효과는 미리 합산, 조건은 숫자 코드, 효과 없을 때 조회 생략 → +4% (12.2ms) |
| Godot 테스트가 멈춘 것처럼 보임 (파스 검사는 통과) | 실행 로그 | `Dictionary.get()` 타입 추론 오류 4곳 수정. 테스트 도구가 `SCRIPT ERROR` 를 보면 바로 중단하도록 개선 (15분 대기 → 20초) |
| 경기 중 저장 후 이어서 하면 이후 전개가 달라짐 | `test_save.gd` 끝까지 비교 | 마지막 입력 뒤 난수 상태와 CPU 작전 캐시까지 저장 |
| 상단 바 「?」 버튼이 화면 밖으로 밀림 | 스크린샷 | 제목 옆으로 이동 |
| 웹 빌드에서 성능 측정 스크립트를 못 찾음 | 브라우저 콘솔 | 내보내기에서 `tests/` 가 빠지므로 `scripts/dev/` 로 이동 |
| 경기 많은 날 휴대폰에서 4.6초 | CPU 제한 측정 | 작전 없는 타석을 연출 계산 없이 처리하는 빠른 경로 (확률 동일). 일반 경로와 통계 비교 테스트 추가 (400경기: 득점·타율·삼진·볼넷·홈런·투구수) |

## 2. 새 로드맵

### P1 — 다음 라운드

1. **CPU 경기 타석 단위 약식 계산**
   - 근거: 빠른 경로 뒤에도 CPU 4배 제한에서 경기 많은 날 3.1초. 경기 하나가 약 11ms 이고 그중 3ms 는 준비(선수 변환·오더), 8ms 는 투구 계산.
   - 내용: 타자·투수 능력으로 타석 결과 확률을 바로 계산 (삼진·볼넷·안타 종류·아웃 종류), 투구수는 분포에서 뽑기. 선수 변환 결과를 하루 안에서 재사용.
   - 검증: 일반 경로와 통계 차이 (득점 ±0.3, 타율 ±.008, 삼진·볼넷 ±1%p, 투구수 ±5), CPU 4배 제한에서 경기 많은 날 1.5초 이하.
2. **작전 성공 확률 안내**
   - 근거: 특수능력·작전이 많아져 초보자가 판단하기 어렵다.
   - 내용: 도루·번트·스퀴즈·히트앤런 버튼에 대략적인 성공 가능성(상·중·하)과 관련 특수능력 표시.
   - 검증: 엔진 확률 계산을 재사용해 표시값과 실제 성공률(1000회 시뮬레이션)의 등급이 일치.
3. **특수능력 발동 연출**
   - 근거: 「발동」 칩은 있지만 실황 문구에 능력 이름이 나오지 않아 효과가 잘 느껴지지 않는다.
   - 내용: 능력이 결과에 영향을 준 타석에 "찬스◎ 발동!" 실황, 금특 선수 등장 시 컷인.
   - 검증: 1경기 관전 스크린샷, 실황 문구 빈도(경기당 2~6회).
4. **비시즌 콘텐츠**
   - 근거: 10~2월에는 연습 경기·스카우트뿐이다.
   - 내용: 동계 합숙 장소 선택(비용·효과), 학교 행사 이벤트, 3학년 진로 상담.

### P2

5. **기록·명예의 전당**: 시즌 개인 타이틀(타율·홈런·다승), 졸업생 프로 성적 추적, 학교 역대 기록
6. **포지션 컨버전·투타 겸업** (오더 화면에서 「적성↓」가 자주 보임)
7. **CPU 학교 흥망**: 신흥 강호, 명문 몰락, CPU 시설 투자
8. **장터 확장**: 시기 한정 상품(여름 대회 전, 연말 대바겐), 가방 일괄 사용
9. **세이브 크기 줄이기**: 지금 2MB, 저장 문자열 변환이 CPU 4배 제한에서 0.7초. 오래된 소식·CPU 선수 기록 정리
10. **프로 명단 연 1회 갱신 가이드**: 실명 명단(`pros.json`) 갱신 절차를 CLAUDE.md 에 정리

### P3

11. **웹 첫 로딩 경량화**: 폰트 TTF 약 12MB → 한글 서브셋, 로딩 화면
12. **응원가·BGM 추가**: 학교별 응원가, 결승전 전용 곡
13. **모바일 큰 글씨 모드**: 640×360 기준 버튼 높이 16px
14. **웹 기반 시스템 ↔ Godot 동등성 검사 강화**: 결정적인 부분은 값 일치, 나머지는 통계 분포 비교
